# locus-link 产物设计

## 简述

locus-link 在 Windows 和 Linux 提供完整产物与 backend 产物：完整产物内嵌 Web UI，backend 保留同一 CLI 与 Web API、但不包含页面资源。两者复用同一个 Core 和 `/api/v0` 契约。

## 职责

本文是产物组成、构建依赖和用途的权威说明；脚本用法见 [`scripts/README.md`](../../scripts/README.md)，CLI 与 HTTP 行为分别见[CLI 契约](contracts/CLI契约.md)和[本机 Web 契约](contracts/Web契约.md)。

## 产物

| 产物 | 组成 | 构建入口 | 用途 |
| --- | --- | --- | --- |
| `temp/bin/locus.exe` / `temp/bin/locus` | Core、CLI、Web API、内嵌 Web UI | `scripts/build.ps1` / `scripts/build.sh` | 最终交付与内嵌页面调试 |
| `temp/bin/locus-backend.exe` / `temp/bin/locus-backend` | Core、CLI、Web API | `scripts/build-backend.ps1` / `scripts/build-backend.sh` | CLI 使用及前后端分离开发 |

完整产物先生成 `internal/web/ui/dist/`，再将其嵌入 executable。后端产物不导入页面资源、不要求 `dist/`，也不调用 pnpm；其非 API 页面路径返回 `404`。

## 发布版本

仓库根目录 `VERSION` 是应用版本的唯一来源。构建脚本把 version、Git commit 与 `complete|backend` artifact kind 写入 executable；`locus version --json` 同时报告当前应用版本、唯一受支持的上一应用版本和 State schema version。安装目录的 `release.json` 保存同一元数据、已安装文件 SHA-256 与安装时间，不以文件时间或文件名猜测版本。

应用版本与 State schema version 独立演进。SQLite 使用 `PRAGMA user_version` 标识 State schema；Registry 的 `api_version` 仍是独立公共契约，不随 executable 部署静默改写。

## 部署与迁移

Windows 每用户 Locus 根默认为 `%USERPROFILE%\.locus\`：完整 executable 位于 `bin\locus.exe`，发布清单位于根目录 `release.json`，Registry、cache、State 与 backups 使用同根下的独立子目录。项目内更近的 `.locus` 覆盖用户根；搜索命中用户目录的 `.locus` 时 `root_origin` 为 `user`。部署不修改用户或系统 `PATH`。`scripts/deploy.ps1` 构建 `complete` 产物、读取当前安装版本、确认升级路径、备份、调用 `scripts/migrate.ps1`、替换 executable、写入发布清单，最后执行已安装产物的 version smoke check。

部署和独立迁移都是 `ConfirmImpact=High` 的 PowerShell 操作，默认通过 `ShouldProcess` 请求确认并支持 `-WhatIf`。自动化只有在路径全部定向到受控工作区时才可显式传入 `-Confirm:$false`。

迁移只接受“上一 State schema → 当前 State schema”，当前版本重复执行为 `no_change`，空 State 初始化为当前版本，其他版本一律拒绝。结构变化前使用 SQLite `VACUUM INTO` 生成一致备份；部署还备份旧 executable 与 `release.json`。迁移或安装任一步失败时，部署恢复 State 和旧安装。

部署只自动迁移 locus-link 拥有的本机 State DB。用户级或项目 Registry 是公共声明，不得由部署扫描或静默重写；未来 Registry `api_version` 变化必须由显式、指定路径的 Registry migration 处理。

## 部署验收

部署完成至少证明：

1. 已安装 `locus.exe version --json` 返回目标版本、`complete` artifact 与当前 State schema；
2. 新安装可以初始化用户 Registry；
3. `locus validate --json` 能读取该 Registry 并返回 complete/valid；
4. 同版本再次部署得到 `state_migration: no_change`，不破坏既有 Registry 或 State。

## 开发组合

分离开发分别运行 `scripts/start-web-api.ps1` 与 `scripts/start-web-ui.ps1`：Go API 固定监听 `127.0.0.1:7070`，Vite 固定监听 `127.0.0.1:5173` 并代理 `/api`。最终形态由 `scripts/start-web.ps1` 构建并启动，只运行完整 executable。

两种 Go 启动入口复用 `temp/e2e-run/` 的 Project Alpha fixture；fixture 缺失时先运行 `scripts/test-e2e.ps1`。
