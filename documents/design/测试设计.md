# locus-link 测试设计

## 简述

本文以工作区内可运行的 concrete environment cases 验证公共契约与设计不变量。测试重点不是证明抽象存在，而是证明陌生 Agent 能通过 CLI 或 WebUI 获得可解析、可复用的 situated operational knowledge，并把实际 action 交给合适的 native tool。

Scope graph 与 Source 行为见[基础 Scope 设计](base-Scope设计.md)，用户根入口、项目登记和 remote cache 见[用户级 Locus 设计](base-用户级Locus设计.md)，当前已通过的实现基线见[当前实现快照](../current-architecture.md)。

## 职责

本文负责：

- 定义跨 Scope、Resolve、native Provider、Observation、documentation 和 Source provenance 的验收场景；
- 定义递归 import graph、回边阻断、partial diagnostics、用户级 Locus 和 remote cache 的目标 E2E；
- 规定工作区隔离和可复现产物。

本文不负责固定测试框架、SQLite schema、Git/HTTP 实现或外部服务部署。Profile、actor、MCP runtime、PostgreSQL/Gitea 扩展和执行层当前冻结，不建立占位 fixture。

## 通用验证基准

- 从根 Scope 的 semantic Binding 开始，不要求调用者先知道 canonical ID；
- Declared View 只包含根 Scope 与成功收集的显式 import graph；
- Scope 按 `scope_id` 去重，alias path 不改变 canonical identity；
- 回环只阻断回边，其他已校验节点保持可用；
- partial view 始终携带 blocked-import diagnostics，不声称候选集合完整；
- Binding、canonical Entity、显式 Route、`requires/provides`、native provider binding 和 Source provenance 可结构化查询；
- Resolve 前后 Registry、登记表、cache metadata 和 Observation 数量不变；
- Probe 只记录实际测量的已校验 Link；
- Observation applicability 区分 declaration/source digest、vantage、effective binding、Probe kind/version 和 relevant context fingerprint；
- Secret 只使用 reference，不进入 Registry、cache metadata、结果、错误或 Observation；
- documentation 只能解析到 owning Scope `docs/`，并保留 Source commit/digest provenance；
- 不要求 locus-link Core 执行 SQL、部署、SSH session 或文档中描述的 MCP 操作；
- 外部 native、Git 和 HTTP 行为由工作区内确定性 helper 模拟；
- 用户级 Locus、Registry、cache、State DB 和测试状态全部定向到工作区；
- 测试结束保留 `temp/e2e-run/`。

若结果只返回未解析的 README/YAML，而没有 canonical identity、Binding、Route、capability、provider binding、evidence、documentation association、completeness 和 provenance，测试应失败。

## 当前 native vertical slice

现有 FRP + SSH / Salt E2E 使用同一项目 Registry 和两份 workstation-local mechanism bindings，必须持续证明：

- canonical Entity、Binding、Link/Route identity、capability、documentation 和声明 provenance 保持一致；
- executable、配置路径、localhost endpoint 等 invocation details 可以按 workstation 不同；
- workstation A Probe 产生的 Observation 只适用于相同 declaration、Source、binding、Probe semantics、vantage 和 relevant context；
- workstation B 使用不同 mechanism binding 时仍能 Resolve 相同 Route，但 A 的 success 在 B 下为 `unknown`；
- Route 后续 Link 可以拥有与第一条 Link 不同的 `from`；
- Resolve 不执行 Probe，Route Probe 只为实际测量的 Link append，Route 本身不落 Observation。

Core 回归测试分别改变 Link declaration、Source content digest、mechanism binding、Probe semantics version、无关 context 字段和 vantage，验证只有完整 applicability 条件成立时 Observation 才成为 Evidence。

## E2E A：Scope graph 与用户级 Locus

### Fixture

在 `test/e2e/case/` 保存可审阅声明，运行时物化为：

```text
temp/e2e-run/
├── user-locus/
├── projects/
│   ├── alpha/
│   └── beta/
└── scopes/
    ├── customer/
    ├── platform/
    └── shared/
```

图至少表达：

```text
project.alpha → user → customer → platform → shared
project.beta  → user
shared        → customer    # 回边
```

`project.alpha` 还通过第二条 alias path 到达 `shared`，用于验证去重和多 alias。

### 必须覆盖

- 项目外运行以用户 Scope 为根；
- 项目内运行以项目 Scope 为根，项目 Registry 显式 import 用户 Scope；
- 用户登记表反向记录 alpha/beta，但不会把项目声明并入用户 Scope；
- 长 import path 可以解析，最终 object identity 仍是 `scope_id::local_id`；
- 同一 `scope_id` 经不同 alias path 到达时只加载一次，并保留全部 provenance；
- 不同 Scope 使用相同 local ID 时，canonical ID 与 alias path 可明确区分；
- `shared → customer` 回边被阻断，其他 Scope 保持可查询；
- Graph/List/Show 返回已加载内容和 blocked edge；
- Resolve 在 partial view 中可以返回已发现 Route，但明确候选集合不完整；
- 已完整加载的 Link 在 partial view 中仍可显式 Probe；
- 相同 alias 指向不同 Scope 时不绑定该 alias，并提示修改；
- 相同 `scope_id` 的两份不同内容不按遍历顺序选择，不允许 alias 掩盖冲突；
- 显式根选择绕过默认项目/用户根 discovery。

## E2E B：Remote cache 与 refresh

### Fixture

使用工作区内确定性 Git/URL helper，模拟：

- Git requested branch `main` 对应 immutable commit；
- URL 内容、ETag/Last-Modified 和响应失败；
- valid、invalid、unchanged 和 updated Registry；
- documentation containment 与越界内容；
- 不包含真实凭据的 opaque credential references。

测试不得连接真实网络、用户 Git 配置、凭据或外部服务。

### Git 验收

- 首次 refresh 在隔离目录 fetch，严格校验后原子激活；
- metadata 同时记录 requested `main`、resolved commit 和 content digest；
- 普通 Resolve/Graph/Probe 不执行 fetch；
- 更新 `main` 后，只有显式 refresh 才切换到新 commit；
- invalid candidate 不覆盖 active cache；
- fetch/校验失败继续使用最后有效 commit，并报告 refresh error；
- 修改显式 Import Source 后 refresh 即完成 Source 切换，canonical identity 不变。

### URL 验收

- 实际内容以 validated content digest 标识；
- ETag/Last-Modified 只用于条件请求优化，不代替 digest；
- digest 未变化时不产生新的 active revision；
- 新内容完整校验成功后才原子激活；
- 首次获取失败且无缓存时只阻断对应 import edge；
- 已有缓存时刷新失败继续使用最后有效内容；
- Source URI、metadata、diagnostics 和日志不泄漏 credential value。

### Documentation 验收

- remote documentation 保留 owning Scope、canonical association、resolved commit/content digest；
- 正文只能从所属 Scope `docs/` containment 内读取；
- `..`、绝对路径和 symlink 越界均失败；
- 文档可以包含 MCP 操作说明，但测试只验证其作为 opaque 文本被安全读取，不实例化 MCP tool。

## E2E C：失败与可用性

必须区分以下状态：

| 场景 | Declared View | 行为 |
|---|---|---|
| 所有 imports 成功 | complete | Resolve 基数结论完整 |
| 回边被阻断 | partial | 其他节点可用，返回循环路径 |
| 首次 remote 获取失败 | partial | 其他节点可用，返回 blocked Source |
| refresh 失败但有有效缓存 | complete | 使用旧 revision，并返回 refresh error |
| 相同 Scope 内容冲突且无有效 authority | partial | 冲突 Scope 不进入可用图 |
| Registry 自身校验失败 | 节点不可用 | 不执行该节点 Probe，不写 Observation |

测试必须证明 partial 不是静默成功：CLI/Web JSON 和 diagnostics 都能区分“对象不存在”“import 被阻断”和“当前现场不可用”。

## 冻结范围

以下内容不进入当前 fixture、schema 或验收门禁：

- Profile 与独立 actor；
- MCP Adapter、Provider、Resource、SafeProbe 或 tool transport；
- PostgreSQL/Gitea 专用 Provider；
- 自动 Route discovery、ranking；
- Plan、Instance、Execute、Supervise、Teardown；
- 通用 Credential Source 系统。

只有真实 native E2E 证明现有 Scope、Route、Provider 和 Observation 语义不足时，才增加最小字段或重新打开对应设计。

## Fixture 与运行目录

- 可审阅声明和模拟设备状态：`test/e2e/case/`；
- 运行时物化目录：`temp/e2e-run/`；
- helper executable：`temp/e2e-run/bin/`；
- 用户级 Locus、remote cache、项目登记和 Observation Store：全部位于 `temp/e2e-run/`；
- Observation Store 通过 `LOCUS_STATE_PATH` 或后续等价测试配置显式重定向；
- 完整复现入口：`scripts/test-e2e.ps1`。

当前自动 E2E 使用真实 `locus`/`locus web` 子进程和确定性 helper。新增 Git/URL fixture 同样不得读取工作区外的用户配置、Credential Manager、SSH Agent、网络状态或文件。

## 维护规则

- 新样例必须对应真实 operational path 或关键不变量；
- 新 Source/Scope 场景优先扩展上述 graph/cache fixture；
- 冻结项不得以 placeholder schema、mock API 或空实现进入契约；
- 公共契约变化时同步 fixture、断言和当前实现快照；
- 设计目标与当前实现事实必须分开陈述。
