# Locus Link 测试设计

## 简述

本文维护 Locus Link 的端到端测试基准和关键样例。测试实现与运行结果以代码和可执行测试为准。

- 当前实现范围见 [`../current-architecture.md`](../current-architecture.md)
- 产品模型见 [产品设计](产品设计.md)
- CLI 与声明字段见[公共契约](contracts/README.md)

## 职责

- 记录端到端测试的共同约束；
- 记录需要长期保留的关键样例；
- 约束 fixture、helper、凭据和测试状态的边界。

## 测试基准

- 从 Project 语义名称开始执行完整 CLI 流程；
- 覆盖 Binding、canonical Entity、显式 Route、Provider 原生上下文和 Observation；
- Resolve 前后不增加 Observation；
- Probe 只记录实际探测的 Link；
- 再次 Resolve 能读取当前 vantage 的最新证据；
- Secret 只使用引用，不进入声明、输出、错误或 Observation；
- documentation reference 只能解析到所属 Scope Registry 的 `docs/`，不得通过绝对路径、遍历或符号链接越界；
- Provider 原始 stdout/stderr 不进入输出、错误或 Observation；失败只返回稳定诊断类别；
- documentation references 能随目标和 Route 返回；
- 外部行为由工作区内确定性 helper 模拟；
- Observation Store 和全部运行状态定向到工作区；
- CLI 与本机 Web API 必须复用同一物化 Registry、helper 和 Observation Store；Web Probe 的 evidence 更新及 vantage 隔离必须与 CLI 一致；
- Graph 不输出 Provider data 或 Secret reference；Knowledge 只返回声明引用并受 `docs/` containment 约束的文档；
- 自动 E2E 通过真实 `locus web` 子进程验证 HTTP 与嵌入式 UI 入口；浏览器视觉与交互 QA 在 Web 行为变更时另行执行，不让测试依赖工作区外安装的浏览器。
- 测试结束保留 `temp/e2e-run/` 供人工复现。

## 关键样例

### PostgreSQL 直连

前置：

- Project Binding `production-db` 指向 canonical database Entity；
- Entity 保存 host、port、engine 和 database；
- PostgreSQL Link 保存 user、Provider 选项和 Secret reference；
- 声明关联数据库操作、迁移和排障文档；
- helper 模拟 PostgreSQL endpoint / Provider Probe。

操作：

```text
locus resolve production-db --capability sql.execute
```

预期：

- 返回正确的 canonical database Entity；
- 返回 PostgreSQL Link 和 `psql` 原生连接上下文；
- 返回 Secret reference，不返回密码；
- 返回当前 Observation 和相关 documentation references；
- 不执行 SQL，不连接真实生产数据库。

### Gitea + FRP + Worker CI/CD

前置：

- Project Bindings `source`、`ci-worker` 和 `production` 指向对应 canonical Entities；
- 显式 Route 包含 Gitea source、FRP/堡垒可达链路、目标网络 Worker、现有部署机制和生产目标；
- 声明关联部署与排障文档；
- helper 模拟 Gitea、FRP、Worker 和部署状态。

操作：

```text
locus resolve production --capability deploy
```

预期：

- 返回 source、目标 Worker、部署目标和显式 Route；
- 返回各步骤的 Provider 原生上下文；
- 返回 Secret references、当前 Observation 和相关文档引用；
- Route 允许前一步为后一步建立条件，不要求节点严格连续；
- 不连接真实 Gitea、FRP、Worker 或生产服务。

## Fixture 与运行目录

- 可审阅声明和模拟设备状态：`test/e2e/case/`；
- 运行时物化目录：`temp/e2e-run/`；
- helper executable：`temp/e2e-run/bin/`；
- Observation Store：通过 `LOCUS_STATE_PATH` 定向到 `temp/e2e-run/`；
- 完整复现入口：`test/reproduce.ps1`。

## 维护规则

- 新样例必须对应新的真实使用路径或新的关键语义；
- 字段级变化优先扩展现有样例；
- 参数使用真实项目的脱敏信息；
- 产品、CLI 或本机 Web API 契约变化时同步更新 fixture 和断言。
