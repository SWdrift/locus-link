# Locus Link 声明契约

## 简述

本文定义用户、Agent 和自动化共同维护的 Registry YAML 公共契约。它给出 `locus/v0` 的目录布局、Scope composition、canonical identity、Entity / Link / Route schema、Provider data、文档引用和静态校验规则。

产品概念见[产品设计](../产品设计.md)，命令行为见[CLI 契约](CLI契约.md)，内部装载与解析流程见[系统设计](../系统设计.md)。当前代码对本契约的覆盖和偏差见[当前实现快照](../../current-architecture.md)。

## 职责

本文负责：

- 定义 Registry 作者需要读写的 YAML 和目录；
- 定义 `api_version`、严格字段、identity、Import、Binding 和引用规则；
- 定义当前公开 Provider 的 `provider_data`；
- 定义 documentation reference 与 Secret reference 的声明边界；
- 定义 `locus validate` 应执行的静态校验。

本文不负责：

- 定义 CLI 输出、退出码或 Runtime Context 参数；
- 固定 Go struct、Loader、Resolver、Provider interface 或 SQLite schema；
- 描述代码当前已经实现的子集；
- 保存 Secret value、临时端口、session、token 或执行状态。

## `locus/v0` 与严格解码

所有 manifest 和声明对象都使用：

```yaml
api_version: locus/v0
```

声明对象还必须具有明确的 `type`：

```yaml
type: entity # entity | link | route
```

每个 YAML 文件只承载一个文档对象。重复 key、多 document、未知核心字段、错误字段类型和不受支持的 `api_version` 都是声明错误。字段使用 `snake_case`。

兼容演进遵循[公共契约索引](README.md)中的规则。Locus 不把未知字段当作无害扩展静默忽略。

## Registry 布局

Project 与 Environment 使用相同目录结构：

```text
.locus/
└─ registry/
   ├─ scope.yaml
   ├─ entities/
   │  └─ *.yaml
   ├─ links/
   │  └─ *.yaml
   ├─ routes/
   │  └─ *.yaml
   └─ docs/
      └─ *
```

`scope.yaml` 定义 Scope、imports 和 bindings；其余目录保存声明对象及关联资料。文件名用于维护，不参与对象 identity。

## Scope、Import 与 Binding

### Environment manifest

```yaml
api_version: locus/v0
scope:
  id: environment.customer-a
  kind: environment
```

Environment 是可复用声明的 ownership 和 namespace。`locus/v0` 中 Environment 不声明 imports 或 Project Binding。

### Project manifest

```yaml
api_version: locus/v0
scope:
  id: project.liaoyu
  kind: project

imports:
  - alias: customer
    path: ../../../environments/customer-a/.locus/registry

bindings:
  production-host: customer::host.prod-01
```

规则：

- `scope.kind` 只能是 `project` 或 `environment`；
- Project 可以通过本地路径导入 Environment；相对 path 以当前 `scope.yaml` 所在 Registry 目录为基准；
- alias 在 active Project 中唯一，只用于引用，不进入 canonical identity；
- Binding 只表达 `Project role → Entity`，不表示 reachability 或 capability；
- import 是 namespaced additive composition，不做字段 merge、override 或 precedence；
- duplicate Scope ID、duplicate alias、import cycle 和非 Environment import 均为错误。

## Identity 与引用

Scope 内对象使用 local ID：

```text
host.prod-01
link.prod-ssh
route.prod-shell
```

装载后形成 canonical ID：

```text
<scope-id>::<local-id>
```

例如：

```text
environment.customer-a::host.prod-01
project.liaoyu::route.prod-shell
```

Scope ID、local ID、alias 和 Binding role 只使用小写字母、数字、`.`、`_`、`-`；`::` 保留给 canonical identity。

引用形式：

| 形式 | 示例 | 含义 |
|---|---|---|
| active Scope local ID | `link.prod-ssh` | 当前 Scope 内对象 |
| import alias-qualified ID | `customer::host.prod-01` | imported Scope 内对象 |
| canonical ID | `environment.customer-a::host.prod-01` | 已规范化的稳定身份 |
| Binding role | `production-host` | 仅在 target resolution 中映射到 Entity |

local ID 在所属 Scope 的 Entity、Link、Route 全部对象类型中唯一。裸 local ID 不从 imported Scope 猜测；不同 Scope 可以拥有相同 local ID。

## Entity

Entity 表示具有稳定身份、值得独立引用和维护的资源：

```yaml
api_version: locus/v0
type: entity
id: host.prod-01
kind: host
name: Customer A Production 01
labels:
  environment: production
documentation:
  - ref: ../docs/prod-01.md
    title: 生产主机操作说明
```

字段：

| 字段 | 必填 | 含义 |
|---|---|---|
| `api_version` | 是 | 当前为 `locus/v0` |
| `type` | 是 | 固定为 `entity` |
| `id` | 是 | Scope 内 local ID |
| `kind` | 是 | 用于发现和展示，不编码 ownership |
| `name` | 是 | 人类可读名称 |
| `labels` | 否 | 稳定的字符串标签 |
| `documentation` | 否 | 关联资料引用 |

IP、端口、账号、localhost endpoint、session 和 tunnel context 通常属于 Link/provider data 或未来 Instance，不为了图形连续性创建为 Entity。

## Link

Link 表示从某个 operational context 出发，通过一个具体 Provider 触及目标并获得 capability：

```yaml
api_version: locus/v0
type: link
id: link.prod-ssh
from: workstation.dev-a
to: customer::host.prod-01
provider: ssh
requires: [tcp-forward.ssh]
provides: [shell, exec, file-read, file-write]
provider_data:
  user: deploy
  host: 127.0.0.1
  port: 22022
  credential_ref: secret://ssh/customer-a-prod
documentation:
  - ref: ../docs/prod-01.md#ssh
    title: SSH 访问说明
```

字段：

| 字段 | 必填 | 含义 |
|---|---|---|
| `api_version` | 是 | 当前为 `locus/v0` |
| `type` | 是 | 固定为 `link` |
| `id` | 是 | Scope 内 local ID |
| `from` | 是 | 可归一化为 Entity 的引用 |
| `to` | 是 | 可归一化为 Entity 的引用 |
| `provider` | 是 | 已注册 Provider name |
| `requires` | 否 | 前序步骤必须已提供的 capability 字符串 |
| `provides` | 否 | 本 Link 提供的 capability 字符串 |
| `provider_data` | 按 Provider | 用户维护的 Provider-specific 数据 |
| `documentation` | 否 | 关联资料引用 |

`requires` / `provides` 是开放字符串，不形成独立 Capability 对象。Workflow、event、causal、ownership 和 Project membership 不使用 Link 表达。

### `frp-stcp`

```yaml
provider: frp-stcp
provider_data:
  config: X:/Secrets/frp/customer-a.toml
  local_host: 127.0.0.1
  local_port: 22022
```

| 字段 | 类型 | 要求 |
|---|---|---|
| `config` | string | 必填；FRP client 配置的外部 reference/path |
| `local_host` | string | 必填；已有 visitor endpoint host |
| `local_port` | integer | 必填；1–65535 |

该声明不表示 Locus 会启动 FRP visitor。`config` 可以指向由外部机制管理的配置，但配置内容和 Secret value 不进入 Registry 输出或 Observation。

### `ssh`

```yaml
provider: ssh
provider_data:
  user: deploy
  host: 127.0.0.1
  port: 22022
  credential_ref: secret://ssh/customer-a-prod
```

| 字段 | 类型 | 要求 |
|---|---|---|
| `user` | string | 必填，非空 |
| `host` | string | 必填，非空 |
| `port` | integer | 必填；1–65535 |
| `credential_ref` | string | 可选；opaque Secret reference |

### `salt`

```yaml
provider: salt
provider_data:
  minion_id: customer-a-prod-01
```

| 字段 | 类型 | 要求 |
|---|---|---|
| `minion_id` | string | 必填，非空 |

Provider data 的内部 Render 和 Safe Probe 处理见[系统设计](../系统设计.md)。调用者不得依赖未在本契约列出的字段产生语义。

## Route

Route 是人工声明的 ordered Link chain：

```yaml
api_version: locus/v0
type: route
id: route.prod-shell
steps:
  - link: link.prod-frp
  - link: link.prod-ssh
documentation:
  - ref: ../docs/prod-01.md#ssh
```

字段：

| 字段 | 必填 | 含义 |
|---|---|---|
| `api_version` | 是 | 当前为 `locus/v0` |
| `type` | 是 | 固定为 `route` |
| `id` | 是 | Scope 内 local ID |
| `steps` | 是 | 非空、有序 Link 引用 |
| `documentation` | 否 | 关联资料引用 |

Route 不重复声明 `target`、`provides`、priority 或 generic constraints：

- target 从最后一个 Link 的 `to` 推导；
- capabilities 按 step 顺序累计 Link `provides`；
- 每一步 `requires` 必须由更早步骤累计的 `provides` 满足；
- 不要求 `previous.to == next.from`；
- 不自动组合 Link、不做图搜索或隐式 ranking。

## Documentation reference

Entity、Link、Route 可以关联：

```yaml
documentation:
  - ref: ../docs/prod-01.md#ssh
    title: SSH 访问说明
```

规则：

- `ref` 必须是相对包含该引用的声明 YAML 文件解析的路径；词法归一化和符号链接解析后都必须位于所属 Scope Registry 的 `docs/` 内；
- `validate` 检查文档资源存在，不校验 Markdown anchor；
- `title` 可选；
- 文档不覆盖结构化字段，不参与 capability fold、Route applicability 或 Provider rendering；
- 文档和普通输出不得包含 Secret value。

## Secret boundary

Declaration 只保存 reference：

```yaml
credential_ref: secret://ssh/customer-a-prod
```

Secret value、token、私钥、密码、临时凭据和完整敏感配置不得进入：

- Registry YAML；
- canonical declared view；
- CLI JSON；
- NativeContext；
- Observation evidence/error；
- 日志和测试 fixture。

Locus 不隐式读取用户凭据补全声明。Secret value 的解析和注入由外部机制或未来 Instance 层负责。

## 静态校验

`locus validate` 在不连接 endpoint、不运行 executable、不读取 Observation 的前提下检查：

1. `api_version`、YAML 文档数量、严格字段和字段类型；
2. Scope kind、Import、Binding、alias 和路径结构；
3. ID 格式、Scope identity 和各对象 identity 唯一性；
4. Entity、Link、Route 引用存在且类型正确；
5. alias-qualified 引用能够唯一归一化；
6. Route steps 非空且 ordered capability fold 成立；
7. Provider 已注册，`provider_data` 的必填字段、类型、取值和字段间约束有效；
8. documentation reference 指向可发现资源；
9. Secret-specific 字段只接受 reference，不提供内联 Secret value 字段。

静态有效只表示 declared view 自洽，不表示当前机器具有 executable、endpoint 可达、credential 有效或 Route 已经执行。运行时匹配、Safe Probe 和 evidence 处理属于[系统设计](../系统设计.md)。

## 完整组合示例

Environment 声明目标主机与 FRP server；Project 声明当前工作站、两个 Link、Route 和 Binding：

```text
project.liaoyu
├─ imports customer → environment.customer-a
├─ binding production-host → customer::host.prod-01
├─ entity workstation.dev-a
├─ link link.prod-frp
├─ link link.prod-ssh
└─ route route.prod-shell
```

装载后得到：

```text
production-host
→ environment.customer-a::host.prod-01

project.liaoyu::route.prod-shell
├─ project.liaoyu::link.prod-frp
└─ project.liaoyu::link.prod-ssh
```

这组声明只说明“已知如何到达目标”。当前调用是否适用以及最近是否探测成功，由 Runtime Context 和 Observation 决定，不回写 YAML。
