# Locus Link v0 具体设计

本文定义可以立即实现和验证的最小产品。长期语义与非目标见 [`design-v0.md`](design-v0.md)。

删减规则：

> 如果删除一个概念后，首个真实 CLI 闭环仍然成立，就从 v0 删除或后置。

## 1. CLI Contract

CLI 是 v0 的用户和 Agent contract。外层心智模型只有两个核心原语：

```text
resolve = 声明上如何触及目标，并且最近的现实证据如何
probe   = 主动测量现实世界，并写入新的 Link Observation
```

正常循环是 `resolve → probe（需要时）→ resolve`。

### 1.1 Core workflow

| 命令 | 目的 | 副作用 |
|---|---|---|
| `locus resolve <target> --capability <name>` | 解析 Binding、显式 Route、证据和 native context | 无；不执行 Route、不 probe、不写 Observation |
| `locus probe <link-or-route-id>` | 运行 Provider safe probe | 只追加 Link Observation |

### 1.2 Inspection / diagnostics

| 命令 | 目的 | 副作用 |
|---|---|---|
| `locus context` | 显示 active Scope、imports、bindings 和 Runtime Context | 无 |
| `locus show <ref-or-id>` | 显示 reference resolution、canonical identity 和 declaration | 无；不返回 runtime evidence |
| `locus list [entity\|link\|route]` | 发现声明对象 | 无 |
| `locus status [id]` | 查看 Link evidence 或 Route 动态聚合状态 | 无 |

### 1.3 Registry authoring / maintenance

| 命令 | 目的 | 副作用 |
|---|---|---|
| `locus init --scope-kind <project\|environment> --scope-id <id>` | 创建最小 Scope Registry | 创建目录和 YAML；不初始化 Git |
| `locus validate` | 校验 Scope、imports、bindings 和声明 | 无 |

`--json` 是通用 presentation flag。其余 flags 按命令收紧：

| 命令 | command flags |
|---|---|
| `init` | `--registry --scope-kind --scope-id` |
| `validate / list / show` | `--registry` |
| `context / resolve` | `--registry --from --vantage`；`resolve` 另有 `--capability` |
| `probe` | `--registry --from --vantage --timeout` |
| `status` | `--registry --vantage` |

无意义 runtime flag 必须作为 unknown flag 拒绝，不能接受后忽略。默认从 cwd 向上发现 `.locus/registry`；`--registry` 只用于 override、automation、tests 和多 Registry 场景。所有路径通过 Go 跨平台路径 API 处理。

正常结果写 stdout，诊断写 stderr。退出码：

| 代码 | 含义 |
|---|---|
| `0` | 成功 |
| `1` | 内部错误 |
| `2` | 输入或声明校验错误 |
| `3` | Resolve unresolved 或 ambiguous |
| `4` | Probe 完成但失败；stdout 仍返回稳定 JSON |

这些命令不增加领域概念：

```text
Scope + Entity + Link + Route
+ Import + Binding + Canonical Identity
+ Runtime Context + Link Observation
+ Provider-native Context
```

不存在独立 Capability 对象。Capability 只是 Link 的 `requires/provides` 字符串和 Resolve 查询条件。

## 2. v0 决策

| 事项 | v0 决策 |
|---|---|
| 实现 | Go 单一可执行文件 |
| 声明 | YAML；可引用 Markdown |
| Scope | Project、Environment、稳定 Scope ID |
| Composition | Project 通过本地路径 import Environment；namespaced additive |
| Binding | Project role → Entity |
| Identity | local ID + `scope-id::local-id` |
| Route | 显式 ordered Link chain；只解析，不执行 |
| Observation | 只记录 Link；本机 SQLite；canonical subject + vantage |
| Provider | 首个闭环实现 FRP/SSH；第二个异构性验证实现 Salt |

v0 不使用 Graph DB，不下载 Registry，不做版本求解、override 或 precedence。

## 3. 文件布局与 Scope Manifest

Project：

```text
project/
└─ .locus/
   └─ registry/
      ├─ scope.yaml
      ├─ entities/
      ├─ links/
      ├─ routes/
      └─ docs/
```

Environment 可以位于独立目录或仓库：

```text
environments/customer-a/
└─ .locus/
   └─ registry/
      ├─ scope.yaml
      ├─ entities/
      ├─ links/
      ├─ routes/
      └─ docs/
```

Environment manifest：

```yaml
api_version: locus/v0
scope:
  id: environment.customer-a
  kind: environment
```

Project manifest：

```yaml
api_version: locus/v0
scope:
  id: project.liaoyu
  kind: project

imports:
  - alias: customer
    path: ../../../environments/customer-a/.locus/registry

bindings:
  production-host: customer::host.prod-01
```

约束：

- `scope.id` 在一个 Context 中唯一且稳定。
- `scope.kind` 仅为 `project | environment`。
- Import path 相对当前 `scope.yaml` 解析。
- Alias 在当前 Project 中唯一，不参与 canonical identity。
- v0 只允许 Project import Environment。
- Import 循环、重复 Scope ID 和重复 alias 均为错误。
- Import 只增加声明；Project 不能覆盖 imported declaration。

## 4. Identity、Composition 与 Binding

声明文件保存 Scope 内 local ID：

```text
host.prod-01
link.prod-ssh
route.prod-shell
```

加载后计算 canonical ID：

```text
environment.customer-a::host.prod-01
project.liaoyu::route.prod-shell
```

规则：

- local ID 在所属 Scope 的全部对象类型中唯一。
- Scope ID、local ID、alias 和 role 使用小写字母、数字、`.`、`_`、`-`。
- `::` 保留给 canonical identity。
- alias-qualified 引用加载后归一化为 canonical ID。
- 同名 local ID 可以存在于不同 Scope。
- CLI 和 Observation 输出 canonical ID。

Composition 只做 namespace 归一化和集合并集：

```text
Project Declarations
+ Imported Environment Declarations
→ Composed Declared View
```

不合并同名对象，不做字段 merge、override 或 precedence。Imported declaration 在 composed view 中只读。

Binding 是：

```text
Project role → canonical Entity
```

Binding 不是 Entity 或 Link，不表示 reachability，也不提供 capability。v0 Binding 目标必须是 imported 或 Project-local Entity。

## 5. 声明格式

所有对象使用：

```yaml
api_version: locus/v0
type: entity # entity | link | route
```

未知核心字段报错；`provider_data` 由对应 Provider 校验。字段使用 snake_case。

### 5.1 Entity

```yaml
api_version: locus/v0
type: entity
id: host.prod-01
kind: host
name: Customer A Production 01
labels:
  environment: production
documentation:
  - ref: ../docs/prod-01.md
    title: 生产主机操作说明
```

Entity 必须具有稳定身份和独立引用价值。IP、端口、用户名、localhost endpoint、session 和 tunnel context 不作为 Entity。

`kind` 只用于发现和展示，不编码 Project/Environment ownership。

### 5.2 Link

首个 slice 在 Environment 中声明真实目标和 FRP server，在 Project 中声明当前工作站以及以下两个 Link。

FRP：

```yaml
api_version: locus/v0
type: link
id: link.prod-frp
from: workstation.dev-a
to: customer::frps.primary
provider: frp-stcp
provides: [tcp-forward.ssh]
provider_data:
  visitor: customer-a-ssh
  config: X:/Secrets/frp/customer-a.toml
  local_host: 127.0.0.1
  local_port: 22022
```

SSH：

```yaml
api_version: locus/v0
type: link
id: link.prod-ssh
from: workstation.dev-a
to: customer::host.prod-01
provider: ssh
requires: [tcp-forward.ssh]
provides: [shell, exec, file-read, file-write]
provider_data:
  user: deploy
  host: 127.0.0.1
  port: 22022
  credential_ref: secret://ssh/customer-a-prod
  host_key_alias: customer-a-prod-01
```

Link 规则：

- `from` 和 `to` 解析到 Entity；跨 Scope 引用使用 alias 或 canonical ID。
- `provider` 表示具体机制。
- `requires/provides` 是开放的稳定字符串，不建立封闭枚举。
- Link 只表达 operational capability/reachability。
- Workflow、event、causal 和 ownership 关系不允许进入 Link。
- Secret 值不进入声明；只保存引用或外部配置路径。

FRP 的 localhost endpoint 是 `provider_data`，不是 Entity。

### 5.3 Route

```yaml
api_version: locus/v0
type: route
id: route.prod-shell
steps:
  - link: link.prod-frp
  - link: link.prod-ssh
documentation:
  - ref: ../docs/prod-01.md#ssh
```

Route 只有 ordered Link steps 和可选文档。它不重复声明 `target`、`provides`、`priority` 或 generic `constraints`：

- target 从最后一个 Link 的 `to` 推导；
- 可提供能力由按顺序累计的 Link `provides` 推导；
- 多条匹配 Route 不自动选择；canonical Route ID 只用于稳定 candidates 展示顺序。

结构校验按声明顺序折叠 capability：

1. 全部 Link 引用存在。
2. 每一步 `requires` 已由前序步骤累计 `provides` 满足。

Provider 可用性和 operational applicability 在 Resolve 时根据 Runtime Context 判断，不属于 declaration schema。

不要求相邻步骤满足 `previous.to == next.from`。上例中 FRP Link 到达 FRP server，SSH Link 从同一工作站经本地转发触及目标主机；组合依据是 `tcp-forward.ssh`，不需要创建 localhost endpoint、session 或 tunnel Entity。

v0 不自动组合 Link，不做图搜索。

### 5.4 Markdown 引用

- `ref` 相对当前 YAML 文件解析。
- `validate` 检查文件存在；不校验 Markdown anchor。
- Markdown 不参与 capability 推导或字段覆盖。
- Markdown 和普通输出不得包含 Secret 值。

## 6. Runtime Context

默认从 cwd 向上查找 `.locus/registry/scope.yaml`，也可用 `--registry` 指定。

- 找到 Project：加载 Project、imports 和 bindings。
- 找到 Environment：直接作为 active Scope；没有 Project Binding。
- 找不到或存在歧义时明确报错。

v0 Runtime Context 只有真实 CLI 和首个 slice 使用的字段：

```yaml
cwd: X:/Projects/liaoyu
current_entity: project.liaoyu::workstation.dev-a
available_tools: [frpc, ssh]
vantage: office-lan
```

用途：

- `cwd`：发现 active Registry。
- `current_entity`：判断 Link `from` 是否适用于当前调用位置；可由 `--from` 指定。
- `available_tools`：判断 Provider 是否可用。
- `vantage`：选择适用 Observation；可由 `--vantage` 指定。

没有显式 vantage 时，使用稳定的 host-specific fallback，不把本机结果当作全局证据。

`locus context` 输出 active Scope、imports、bindings、以上 Runtime Context 和加载警告。v0 不加入 `principal`、runtime `credential_refs`、`calling_agent` 或 generic constraints。

## 7. Link Observation

### 7.1 记录

Observation 只针对 Link：

```yaml
id: obs-01J...
subject: project.liaoyu::link.prod-ssh
vantage: office-lan
status: success
observed_at: 2026-08-30T10:15:00Z
expires_at: 2026-08-30T10:30:00Z
provider: ssh
evidence:
  host_key_fingerprint: SHA256:...
error: null
```

规则：

- `subject` 必须是 canonical Link ID。
- `status` 为 `success | failure | unknown`。
- `observed_at` 必填；`expires_at` 可选。
- evidence/error 必须脱敏。
- Observation 只追加，不更新 declaration。
- vantage 必填；自动检测失败时使用 host-specific fallback。

Entity、Route 和 capability 不存独立 Observation。

### 7.2 Vantage 与 Route 聚合

只有 vantage 完全匹配且未过期的 Observation 才作为当前证据。其他 vantage 和过期记录可以展示，但不证明当前可用。

Route 状态从必要 Link 聚合：

- 任一 Link 有适用 fresh failure：`failure`。
- 全部 Link 有适用 fresh success：`success`。
- 每条 Link 都有当前 vantage 的记录、没有 failure，且至少一条记录已过期：`stale`。
- 其余：`unknown`。

Route 状态不落库。

### 7.3 本机 Store

v0 使用一个本机 SQLite 文件：

- Windows：`%LOCALAPPDATA%/locus-link/state.db`。
- Linux/macOS：`$XDG_STATE_HOME/locus-link/state.db`，未设置时使用 `~/.local/state/locus-link/state.db`。

Store 只需要：

- 追加 Link Observation；
- 按 canonical Link subject 和 vantage 查询最新记录；
- 判断 `expires_at`。

不设计共享/global Store、远程数据库、可插拔 Store interface 或多实例写入。

## 8. Resolve

构造顺序：

```text
Discover Active Scope
→ Load Imports
→ Canonicalize IDs
→ Additive Composition
→ Resolve Bindings
→ Collect Runtime Context
→ Query Link Observations
→ Resolve Declared Routes
```

Target 按顺序解析：

1. active Project Binding role；
2. canonical Entity ID；
3. import alias-qualified Entity ID；
4. active Scope local Entity ID。

不从多个 imported Scope 猜测裸 local ID。

候选 Route 必须：

- 最后一个 Link 的 canonical `to` 等于解析后的 target；
- 按顺序折叠后包含请求 capability；
- Link 引用、`requires/provides` 和 Provider data 有效；
- Provider 已注册；
- v0 中每个 Link 的 `from` 与 `current_entity` 相同。

最后一条限制是首个 slice 的明确边界，不推断执行后位置，也不制造 session Entity。真实路径需要其他 applicability 时，再以具体 Provider 案例扩展。

Candidate cardinality 是结果规则，不是 ranking：

- 0 candidate → `unresolved`；
- 1 candidate → `resolved`，返回 `route`；
- 多个 candidate → `ambiguous`，返回全部 `candidates`。

不得按 evidence success/failure、cost、YAML 顺序、Provider 类型、hop 数或最近成功时间自动选择。Candidates 只按 canonical Route ID 排序以稳定输出；这个展示顺序没有推荐语义。Observation 可以描述 Route 最近是否成功，不能成为 v0 自动决策器。

`locus resolve production-host --capability shell --json` 的 resolved 输出：

```json
{
  "status": "resolved",
  "input_target": "production-host",
  "canonical_target": "environment.customer-a::host.prod-01",
  "capability": "shell",
  "route": {
    "canonical_id": "project.liaoyu::route.prod-shell",
    "derived_target": "environment.customer-a::host.prod-01",
    "derived_provides": ["shell", "tcp-forward.ssh"],
    "evidence_status": "stale",
    "steps": [
      {
        "link_id": "project.liaoyu::link.prod-frp",
        "provider": "frp-stcp",
        "native_hint": {
          "executable": "frpc",
          "args": ["-c", "X:/Secrets/frp/customer-a.toml"]
        },
        "evidence": {"link_id": "project.liaoyu::link.prod-frp", "status": "stale"}
      },
      {
        "link_id": "project.liaoyu::link.prod-ssh",
        "provider": "ssh",
        "native_hint": {
          "executable": "ssh",
          "args": ["-p", "22022", "deploy@127.0.0.1"],
          "credential_refs": ["secret://ssh/customer-a-prod"]
        },
        "evidence": {"link_id": "project.liaoyu::link.prod-ssh", "status": "stale"}
      }
    ]
  }
}
```

`args` 始终是参数数组，不生成 shell 字符串。Resolve 只调用 Provider `Validate` 和 `Render`，读取已有 Observation；它不调用 `Probe`、不写 Observation、不启动 FRP、不建立 SSH session、不执行 Salt operation。

## 9. Probe 与 Status

`locus probe <link-id>` 调用对应 Provider safe probe，并追加一条 canonical Link Observation。

`locus probe <route-id>` 按顺序 probe Route 中的 Link：

- 每个实际尝试的 Link 都追加 success/failure/unknown Observation；
- 前序 Link 失败时停止，后续步骤不写 Observation；
- 不创建或持久化 Route Observation。

首个 slice 的安全边界：

- FRP：检查配置、server 状态或已存在的本地 visitor endpoint；不启动 visitor；
- SSH：检查 TCP endpoint 和 SSH configuration；不建立 session，不执行任意远程命令；
- Salt：只调用 `test.ping`。

Probe 测量既有运行状态，不执行或建立 Route。首个真实案例必须已有外部管理的 FRP visitor，或由用户/Agent 根据 Resolve 返回的 native hint 单独启动。

`locus status` 是 inspection surface，不是正常 workflow 的必经步骤。`status <link-id>` 读取指定 vantage 的最新持久化 Link Observation；`status <route-id>` 从 constituent Link observations 实时聚合 evidence。Status 不修改状态，不读取或持久化 Route Observation，不跨 vantage 混用证据。

## 10. Provider

Provider 是 v0 保留的真实多态边界：

```go
type Provider interface {
    Name() string
    Executable() string
    Validate(link Link) []ValidationIssue
    Render(link Link, ctx RuntimeContext) (NativeHint, error)
    Probe(ctx context.Context, link Link, probe ProbeContext) LinkObservation
}
```

```go
type NativeHint struct {
    Executable     string
    Args           []string
    CredentialRefs []string
}
```

- `Validate` 只校验 provider-specific data。
- `Render` 只生成结构化 native context，不连接目标。
- `Probe` 只执行安全检查并返回 Link Observation。
- 外部进程使用参数数组，不经过 shell 重新解释。
- 不提供通用 `Execute`。

FRP/SSH 完成首个闭环；Salt 作为第二个异构性验证，只实现 `test.ping` NativeHint 与 safe probe。Gitea、Manual 和 DSC 继续后置。

## 12. 测试

只保护可观察 contract：

- Cobra help 中的 core、inspection、authoring 三层命令和 JSON contract。
- cwd 与 nested cwd 的 `.locus/registry` 自动发现及跨平台路径处理。
- declaration 命令不依赖 runtime context；无意义 runtime flags 被拒绝。
- `show binding` 显式输出 input ref、ref type 和 canonical target，且不包含 Observation。
- 完整 Runtime Context：active Scope、imports、Binding、cwd、current Entity、Provider tools、vantage 和 Store path。
- Scope/import/canonical identity，以及 Entity/Link/Route 引用归一化。
- Route target/provides 推导、ordered steps 和 `requires/provides` 折叠。
- Resolve 的 unresolved/resolved/ambiguous cardinality，不进行自动 ranking。
- Resolve 只读取 evidence，不 probe、不写 Observation、不启动或执行 Provider operation。
- Link probe、Route constituent probes、Link-only persistence 和稳定 failure JSON。
- Route status 动态聚合和严格 vantage 隔离。
- FRP/SSH/Salt NativeHint 参数边界、safe probe 边界和 Secret 不泄漏。
- Salt success → failure → recovery 对 Resolve evidence 的影响。

同一规则只在最低成本且最接近用户行为的一层验证。

可审阅的声明与模拟设备状态保存在 `test/e2e/case/`。测试将同一 Project 模板物化为多个 Project，并把可运行副本、helper executable 和 SQLite 保留在 `temp/e2e-run/`；`test/reproduce.ps1` 可重建并重跑整个案例。

## 13. 首个 Vertical Slice

只实现一条真实路径：

```text
Project
→ import Environment
→ Binding production-host
→ canonical target host
→ declared FRP Link
→ declared SSH Link
→ resolve shell
→ probe Route（需要时）
→ append Link Observations with vantage
→ 再次 resolve
```

实现顺序：

1. 用真实、脱敏数据建立一个 Environment 和一个 Project。
2. Environment 声明目标 host 与 FRP server；Project 声明工作站、Binding、FRP Link、SSH Link 和 Route。
3. 实现 `init`、load、canonical identity、import、Binding 和 `validate`。
4. 实现 `context`、`list` 和 `show`。
5. 实现 Route 推导、FRP/SSH Provider render 和 `resolve`。
6. 实现本机 SQLite、FRP/SSH safe probe、`probe` 和 inspection `status`。
7. 再次 Resolve，确认当前 vantage 的 Link Observation 改变 Route evidence。

### 13.1 第二个异构性验证

Salt 使用同一 Scope、Binding、Route、vantage 和 Link Observation 闭环，只增加真实 Provider 行为：

```text
production-host
→ single-Link Salt Route
→ salt <minion-id> test.ping --out=json
→ Link Observation
→ 再次 resolve salt.ping
```

它验证 Provider 多态能够容纳与 FRP/SSH 不同的 native context，而不增加 Capability 对象、Route 特例或 Store abstraction。

## 14. 验收条件

- Cobra CLI 的 core workflow、inspection 和 authoring surfaces 具有稳定、可脚本化的行为。
- Project import Environment 后，Binding 能解析到 canonical target Entity，`show` 明确暴露 Binding → Entity。
- Import 是 namespaced additive composition，无 override/precedence。
- local ID 可跨 Scope 重复，canonical ID 输出明确。
- 声明对象只有 Entity、Link、Route；不存在 Local Capability。
- Route target 和 provides 从 ordered Link steps 推导。
- FRP→SSH 通过 operational applicability 和 `requires/provides` 成立，不创建临时 Entity。
- Observation 只记录 canonical Link subject 与 vantage；Route status 动态聚合，不落库。
- Resolve 返回 canonical target、matched Route、Link evidence 和 provider-native hints，但不执行 Route。
- 多 Route 返回 ambiguous candidates，不根据 evidence 或其他因素自动选择。
- Probe 不执行 Route operational action，不泄漏 Secret；failure 保持稳定 JSON 和非零退出码。
- 第二次 Resolve 能体现第一次 Probe 写入的当前 vantage evidence。
- Salt `test.ping` 通过相同 Link Observation 闭环验证异构 Provider。
